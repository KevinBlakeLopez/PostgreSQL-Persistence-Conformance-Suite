# Recorded evidence

Investigation date: 2026-10-24. Written by: Claude Opus 5.5 (max).

## Layout

`<experiment>/<variant>-<form>[-<tag>]/<UTC stamp>-rep<N>/` holds one repetition. `linux/` repeats that layout for the runs in the Linux container. A tag names the build when it is not 2.2.1 from PyPI: `master`, `fix-d4-a1`, `fix-d4-a2`, `fix-redis-reconnect`. The `durability` tag marks 2.2.1 runs recorded after the final Redis restart check was added.

Each repetition contains:

| File | Contents |
| --- | --- |
| `result.json` | The observations the experiment extracted, the environment (Dramatiq, redis-py, Python, Redis server and its persistence settings, OS, and SHA-256 of the Dramatiq files involved), and any harness error |
| `timeline.jsonl` | The harness's own actions with timestamps: Redis start and stop, worker start, signals, waits, snapshots |
| `witness.jsonl` | Every event the actor and the observation hooks sent to the external witness, with the witness's receive time |
| `snapshots.jsonl` | Every `dramatiq:*` key in Redis at each checkpoint, read over the harness's own connection; payloads summarized |
| `worker-1.log`, `worker-2-replacement.log` | The `dramatiq` CLI's output, with `--verbose` |
| `redis/` | The Redis server's log and append-only files |

Other files:

| Path | Contents |
| --- | --- |
| `SUMMARY.md` | One row per repetition, generated by `reproductions/summarize.py` |
| `minimal/` | Output of the single-file reproductions in `reproductions/minimal/` |
| `linux/upstream-tests/` | Dramatiq's `tests/test_redis.py`, `tests/test_worker.py` and `tests/middleware/test_retries.py` for `master` and each fix |
| `_batch-logs/` | The console output of each batch lane |
| `_harness-development/` | A smoke run that failed on a harness bug (a parameter-name clash in the harness's logger) before any observation was made |

## Paths in the record

Local absolute paths were replaced after recording. `$WORKTREE` is the repository checkout, and `$SCRATCH` is the directory that held the virtual environments and the Dramatiq clone (see the README's "Running it"). In Redis's append-only files each bulk string's length prefix was recomputed, and `redis-check-aof` accepts every file. The generated summaries are unchanged by the replacement.

## Known gaps in the record

Nothing below changes an outcome.

- **The first N2 run** (`n2/fault-url/20261025T023856Z-rep1`) predates the `pause_ms` and `held_after_worker1_exit` fields, and its log markers were taken before worker 1 stopped. Its pause was 15 s, the default.
- **D4 runs from the main batch** (2.2.1 and `master`, without the `durability` tag) have no `places_after_final_redis_restart` field. The check was added afterwards. Runs that have the field (fix builds, `durability`, Linux) restart Redis once more, with no worker running, and look for the message again.
- **One N1 fix run** (`n1/fault-aggressive-host-fix-redis-reconnect/20261025T025813Z-rep1`) ended with a harness error. A snapshot listed an ack set with SCAN that was deleted before TYPE: the fix had just promoted the delayed messages at their ETA, as the snapshot's `dramatiq:default` list shows. The snapshot now skips such keys. An extra repetition replaces this one.
- **The first D4 `control-ok` run** (`d4/control-ok-host/20261025T023250Z-rep1`) used an "attempt 1 acked" wait that matched the original's ack instead of the retry's. Its final snapshot was still taken after attempt 1 finished, and it shows nothing left in Redis. The wait was corrected before the batch.

## Adversarial verification (2026-10-25)

`verify/` holds the runs from `reproductions/verify.py`, laid out as `verify/<experiment>/<variant>-<form>[-<tag>]/<UTC stamp>-rep<N>/`. Besides the files listed above, each run has:

| File | Contents |
| --- | --- |
| `monitor-1.log`, `monitor-2.log` | Redis's `MONITOR` stream, before and after the fault, including the commands run inside the Lua dispatch script (`[0 lua]` lines) |
| `witness.jsonl` | `state` events too, where the in-worker reporter was on (`PPCS_REPORT_STATE=1`) |

Other paths:

| Path | Contents |
| --- | --- |
| `verify/SUMMARY.md` | Grouped results and the regression-test matrix, generated by `reproductions/verify_summary.py` |

| `verify/linux-regression/suite-*.txt` | Dramatiq's suite, minus benchmarks, run with a 60 s per-test timeout |
| `verify/linux-regression/suite-*.hung-attempt.txt` | A first attempt without a timeout, stopped after a test in Dramatiq's own suite hung on unpatched `master` |

| `verify/_batch-logs/` | Console output of each verification lane |
