### F1 — High: the commit plan can accept committed content outside its manifest

**observed.** `R/probe_plan.py` cloned both real repositories with `git clone --shared`, copied in the 75 manifest files, and installed a benign pre-commit hook only in the ORM clone. The confidentiality check was neither disabled nor changed. This is a distinct content-identity failure: both versions can pass that check.

**source reading.** `commit_plan.py:128–140` checks index blobs before `git commit`; `143–160` checks the committed parent, filenames, identity, and message, but no committed blob. A commit hook or another index writer can change a same-path blob after its expected hash was checked. The successful filename comparison cannot detect that. The script does not hold an exclusive checkout-wide lock. A changed HEAD is detected only after a commit has already been made.

**judgment.** Do not run this plan on the actively shared checkouts as prepared. Revalidate content after all changes recommended here, regenerate the manifest, and arrange exclusive index/HEAD access for the commit interval or redesign the process around an isolated snapshot. Post-commit hash validation is necessary but detects a bad commit after creation; it cannot itself prevent races. No history should be reset automatically on failure.
